A. Compressible flow and heating

Textbook: Anderson, Modern Compressible Flow, chapters 3 and 4 (shocks). Anderson, Hypersonic and High-Temperature Gas Dynamics, chapter 6 (boundary layers and heating). White, Viscous Fluid Flow, chapter 7 (compressible boundary layers). Free: NASA Glenn "Oblique shock" and "Normal shock" pages; NACA Report 1135 (tables and formulas).

In the talk: S4. Record: docs/specs/00_decisions.md section 1, physics/atmosphere.py.

Definition

The flight condition is Mach 4.0 at 30 km in the US Standard Atmosphere 1976. The freestream state fixes every other number: static temperature, pressure, speed of sound, viscosity and unit Reynolds number. The wall is isothermal at 300 K. The body is sub-scale, about 0.3 m long.

Key relations
\[ \begin{aligned} a &= \sqrt{\gamma R T}, \qquad U = M a \\ T_0 &= T\left(1 + \tfrac{\gamma-1}{2} M^2\right), \qquad p_0 = p\left(1 + \tfrac{\gamma-1}{2} M^2\right)^{\gamma/(\gamma-1)} = p\left(1 + \tfrac{1}{5} M^2\right)^{7/2} \\ \mu &= \mu_{\mathrm{ref}} \left(\frac{T}{T_{\mathrm{ref}}}\right)^{3/2} \frac{T_{\mathrm{ref}} + S}{T + S} \quad \text{(Sutherland)}, \qquad \frac{Re}{\mathrm{m}} = \frac{\rho U}{\mu} \end{aligned} \]
More relations
\[ \begin{aligned} \rho &= \frac{p}{R\,T}, \qquad c_p = \frac{\gamma R}{\gamma - 1} \\ H &= \frac{r_0\, z}{r_0 + z}, \qquad T = T_b + L\,(H - H_b), \qquad p = p_b \left(\frac{T_b}{T}\right)^{g_0 M_0 / (R^{*} L)} \quad \text{(1976 formula, 20 to 47 km)} \end{aligned} \]

Why 30 km and not a lower, more realistic altitude?

At 30 km the unit Reynolds number is 1.5e6 per meter, so a 0.3 m body stays below Re 5e5 and the laminar model is defensible. At 25 km the same body would be near transition and a turbulent model would be required. The choice is stated as a modeling choice, not as a mission.

Why is the wall at 300 K when T0 is 951 K?

A cold wall is the normal test-facility condition and it gives a well-posed heat-flux objective. A radiative-equilibrium wall would add an unknown emissivity and a nonlinear boundary condition. The cold wall also thins the boundary layer, which keeps the flow laminar longer.

What is the total temperature at Mach 4 if T = 226.5 K?

Which function in the repository returns the freestream state?

physics.atmosphere.state(altitude_km). It returns T, p, rho, a and mu for a tabulated altitude.

Definition

A normal shock turns supersonic flow into subsonic flow in a very thin layer. Static pressure, density and temperature rise. Total pressure falls because the shock creates entropy. The loss grows fast with the upstream Mach number.

Key relations (calorically perfect gas, gamma = 1.4)
\[ \begin{aligned} \frac{p_2}{p_1} &= 1 + \frac{2\gamma}{\gamma+1}\left(M_1^2 - 1\right) \\ M_2^2 &= \frac{1 + \frac{\gamma-1}{2} M_1^2}{\gamma M_1^2 - \frac{\gamma-1}{2}} = \frac{1 + \frac{1}{5} M_1^2}{\frac{7}{5} M_1^2 - \frac{1}{5}} \\ \frac{p_{02}}{p_{01}} &= \left[\frac{(\gamma+1) M_1^2}{(\gamma-1) M_1^2 + 2}\right]^{\gamma/(\gamma-1)} \left[\frac{\gamma+1}{2\gamma M_1^2 - (\gamma-1)}\right]^{1/(\gamma-1)} = \left[\frac{6 M_1^2}{M_1^2 + 5}\right]^{7/2} \left[\frac{6}{7 M_1^2 - 1}\right]^{5/2} \end{aligned} \]
More relations
\[ \begin{aligned} \frac{\rho_2}{\rho_1} &= \frac{(\gamma+1) M_1^2}{(\gamma-1) M_1^2 + 2}, \qquad \frac{T_2}{T_1} = \frac{p_2/p_1}{\rho_2/\rho_1}, \qquad \frac{p_{02}}{p_{01}} = \left(\frac{\rho_2}{\rho_1}\right)^{\gamma/(\gamma-1)} \left[\frac{\gamma+1}{2\gamma M_1^2 - (\gamma-1)}\right]^{1/(\gamma-1)} \\ \Delta s &= -R \ln \frac{p_{02}}{p_{01}}, \qquad \pi_{NS}(M) = \frac{p_{02}}{p_{01}}(M) \ \text{for } M \gt 1, \quad 1 \ \text{for } M \le 1 \end{aligned} \]

Implementation: physics/shock.py
  • One private function _jump(M, Mn1, sin_turn) holds the Rankine-Hugoniot relations (NACA 1135 equations 93, 94, 96, 99, 100). It serves both shock types: the normal shock calls it with Mn1 = M and sin_turn = 1; the oblique shock with \(M_{n1} = M \sin\beta\) and \(\sin(\beta - \theta)\).
  • The total pressure ratio is coded as the density ratio to the power \(\gamma/(\gamma-1)\) times the second bracket. That is the same as the first form in the key relations because the first bracket there is the density ratio.
  • normal(M) returns a dict with the five ratios. For \(M \le 1\) it returns all ratios equal to 1 and \(M_2 = M\): no shock. This is why a subsonic streamtube at the throat keeps its total pressure in the objective.
  • postprocess.metrics.pi_normal_shock(M) wraps normal node by node with max(M, 1.0), so the same code gives \(\pi_{NS}\) for the recovery objective.
  • Inputs and outputs are plain floats and dicts, no arrays, so each call can be checked by hand against the NACA 1135 tables. Tests: tests/test_shock.py.

Interview questions
Why does the objective include a normal shock that is not in the CFD?

The inlet feeds a subsonic diffuser, so the flow must pass a terminal shock somewhere. The post-processing takes each streamtube at the throat through a normal shock at its own Mach number. Without this term the best inlet in both objectives is a flat plate, which is not a design.

What is the entropy rise across a shock related to?

To the total pressure ratio: \(\Delta s = -R \ln(p_{02}/p_{01})\). A smaller total pressure ratio means more entropy and more loss.

Self-check
Does total temperature change across an adiabatic shock?

No. Total enthalpy is conserved, so T0 is the same on both sides for a calorically perfect gas.

Definition

A wedge of angle theta in supersonic flow makes an oblique shock at angle beta. Only the velocity component normal to the shock, M1 sin(beta), goes through the shock relations. The tangential component does not change. For a given M1 and theta there are two solutions. The weak solution is the one that occurs on an isolated wedge.

Key relation
\[ \begin{aligned} \tan\theta &= 2\cot\beta\,\frac{M_1^2 \sin^2\beta - 1}{M_1^2(\gamma + \cos 2\beta) + 2} \\ M_{n1} &= M_1 \sin\beta, \qquad M_2 = \frac{M_{n2}}{\sin(\beta - \theta)} \end{aligned} \]
More relations
\[ \begin{aligned} M_{n2}^2 &= \frac{(\gamma-1) M_{n1}^2 + 2}{2\gamma M_{n1}^2 - (\gamma-1)}, \qquad \frac{p_2}{p_1} = 1 + \frac{2\gamma}{\gamma+1}\left(M_{n1}^2 - 1\right), \qquad \frac{p_{02}}{p_{01}} = \frac{p_{02}}{p_{01}}(M_{n1}) \\ \theta_{\max}(M) &= \max_{\mu \lt \beta \lt \pi/2} \theta(\beta; M), \qquad \mu = \arcsin\frac{1}{M} \quad \text{(Mach angle)} \end{aligned} \]

Interview questions
What happens when theta is larger than theta_max?

The shock detaches and becomes a curved bow shock ahead of the wedge. The flow behind the central part is subsonic and the total pressure loss is close to a normal shock. The gates refuse such designs before any mesh is built.

Why validate against an oblique shock first?

It is an exact inviscid solution that tests the solver setup, the freestream, the mesh orientation and the units in one short run. A failure there is a setup bug, and no later result can be trusted until it passes.

In the talk: S2, S8, S20 (the Oswatitsch cut). Record: runs/dev/2026-11-01_inlet_design_point/*/geometry.json, runs/analysis/2026-11-02/oswatitsch_cut.png.

Definition

Two ramps make two oblique shocks before the terminal normal shock. Each oblique shock removes less total pressure than one strong shock. Oswatitsch showed that, for a fixed number of oblique shocks, the total pressure recovery is a maximum when all oblique shocks have the same normal Mach number, M1 sin(beta1) = M2 sin(beta2).

Key relations
\[ \begin{aligned} M_{k+1} &= M_2\!\left(M_k, \theta_k\right), \qquad \frac{p_{0,\mathrm{th}}}{p_{0,\infty}} = \prod_{k=1}^{2} \frac{p_{02}}{p_{01}}\!\left(M_k \sin\beta_k\right), \qquad \mathrm{recovery}_{\mathrm{inviscid}} = \frac{p_{0,\mathrm{th}}}{p_{0,\infty}}\;\pi_{NS}(M_{\mathrm{th}}) \\ \text{Oswatitsch: } & M_1 \sin\beta_1 = M_2 \sin\beta_2 \quad \text{(equal normal Mach numbers, equal shock strength)} \end{aligned} \]

Interview questions
Why not add a third ramp?

More ramps give more recovery, but the design space would have three variables, the body would be longer and the heat load would rise. The study keeps two variables so the Pareto front can be shown on a plane and every point can be checked by hand.

Is your design on the Oswatitsch optimum?

Not by construction. The Oswatitsch condition is near theta2 = theta1 + 2 degrees in this box, and the design map shows the GP mean along that cut against the analytic curve. The Pareto front is defined by two objectives, so its points need not sit on the single-objective optimum.

Self-check
Why is the second shock angle given relative to the first ramp?

The flow after shock 1 is parallel to ramp 1. The second shock turns it by a further theta2, so its angle is measured from the ramp 1 direction.

State the Oswatitsch condition in one sentence.

Equal normal Mach numbers on all oblique shocks give the maximum recovery for that number of shocks.

Definition

recovery_total is the mass-flux-weighted mean of local total pressure at the throat plane, after each streamtube passes a normal shock at its own Mach number, divided by the freestream total pressure. recovery_throat is the same quantity without the terminal shock. The cowl lip is placed where the two oblique shocks meet (shock on lip), so the capture is full at the design Mach number and the cowl position is not a design variable.

Key relation
\[ \begin{aligned} \mathrm{recovery\_total} &= \frac{\sum_i w_i\,\phi_i\,p_{0,i}\,\pi_{NS}(M_i)}{\sum_i w_i\,\phi_i}\;\frac{1}{p_{0,\infty}} \\ \phi_i &= \rho_i\left(u_i n_x + v_i n_y\right), \qquad p_{0,i} = p_i\left(1 + \tfrac{1}{5} M_i^2\right)^{7/2}, \qquad \pi_{NS}(M) = 1 \;\text{for}\; M \le 1 \end{aligned} \]
More relations
\[ \begin{aligned} w_i &= \tfrac{1}{2}\left(s_{i} - s_{i-1}\right) + \tfrac{1}{2}\left(s_{i+1} - s_{i}\right) \quad \text{(trapezoid weights along the throat plane)}, \qquad \mathbf{n} = (\cos\theta_t, \sin\theta_t), \quad \theta_t = \theta_1 + \theta_2 \\ \dot m &= \sum_i w_i \phi_i, \qquad \mathrm{capture\_ratio} = \frac{\dot m}{\rho_\infty U_\infty\, y_P}, \qquad \mathrm{recovery\_total\_bulk} = \mathrm{recovery\_throat}\;\pi_{NS}\!\left(\bar M_{\mathrm{th}}\right) \\ \text{shock on lip: } & O + a\,\mathbf{d}_1 = C + b\,\mathbf{d}_2 = P, \qquad \mathbf{d}_1 = (\cos\beta_1, \sin\beta_1), \quad \mathbf{d}_2 = (\cos(\theta_1+\beta_2), \sin(\theta_1+\beta_2)), \quad h = (P - C)\cdot\mathbf{n}_2 \end{aligned} \]

Definition

Near a wall the flow slows to zero in a thin boundary layer. A laminar layer is smooth and its thickness grows as sqrt(x). A turbulent layer mixes more, so it gives higher skin friction and higher heat flux. Transition from laminar to turbulent depends on the Reynolds number, the Mach number, the wall temperature and the roughness. The study uses the laminar Navier-Stokes equations.

Definition

A finite-volume code stores the mean of the conserved variables in each cell and updates it from the fluxes through the cell faces. The convective flux at a face is an approximate solution of the Riemann problem between the two neighbor states. Roe's flux linearizes this problem. Near a sonic point Roe's flux can admit an expansion shock and on blunt bodies it can show the carbuncle. The entropy fix adds dissipation to the small eigenvalues and removes both. SU2's ENTROPY_FIX_COEFF sets how large that region is.

Why does a limiter hurt convergence?

A non-smooth limiter switches on and off from one iteration to the next, so the residual oscillates instead of falling. Smooth limiters such as Venkatakrishnan's reduce this at the cost of a little extra dissipation.

What order of accuracy do you claim?

Second order in smooth regions by construction. The grid study does not measure an observed order because the changes between levels are too small and not monotone, and the report says "order undefined" rather than quoting one.

Definition

The steady solution is reached by marching in pseudo-time. An implicit Euler step solves a linear system each iteration and allows CFL numbers far above the explicit limit. The CFL number sets the pseudo-time step relative to the cell size and wave speed. CFL adaptation raises the CFL when the residual falls and lowers it when the residual rises. The linear system is solved approximately with FGMRES and an ILU preconditioner.

Krylov subspaces. The implicit step needs the solution of \(\mathbf{A}\,\Delta\mathbf{U} = \mathbf{b}\) with \(\mathbf{A} = (V/\Delta t)\mathbf{I} + \partial\mathbf{R}/\partial\mathbf{U}\). On the medium 8/8 mesh \(\mathbf{A}\) has four unknowns per cell (density, two momenta, energy), so about 122 000 rows, and each row has entries only for the cell and its neighbours: the matrix is sparse. A direct solve by LU factorisation would fill in the sparsity and is too expensive to repeat every pseudo-time step. A Krylov method never factorises \(\mathbf{A}\). It only multiplies \(\mathbf{A}\) by vectors. Starting from the residual \(\mathbf{r}_0 = \mathbf{b} - \mathbf{A}\mathbf{x}_0\), it builds the Krylov subspace, the span of \(\mathbf{r}_0, \mathbf{A}\mathbf{r}_0, \mathbf{A}^2\mathbf{r}_0, \ldots\), one new vector per iteration, and looks for the best correction inside that subspace.

GMRES and FGMRES. GMRES (generalised minimal residual) chooses, among all corrections in the \(m\)-dimensional Krylov subspace, the one that makes the residual \(\|\mathbf{b} - \mathbf{A}\mathbf{x}_m\|\) smallest. The Arnoldi process keeps the Krylov vectors orthonormal and turns the big minimisation into a small least-squares problem of size \(m\). The residual can only fall or stay as \(m\) grows, and each iteration costs one matrix-vector product plus \(m\) dot products. A preconditioner \(\mathbf{M} \approx \mathbf{A}\) that is cheap to invert is applied to every Krylov vector, so the method works on \(\mathbf{A}\mathbf{M}^{-1}\), which is closer to the identity and needs fewer iterations. ILU (incomplete LU) is such an \(\mathbf{M}\): an LU factorisation that keeps only the entries where \(\mathbf{A}\) already has them. FGMRES is the flexible variant: the preconditioner may change from one iteration to the next, which is what SU2 needs in parallel, because the ILU on each MPI rank sees only its own part of the mesh. FGMRES stores the preconditioned vectors as well, so it costs twice the memory of GMRES for the same \(m\), which is harmless at 15 vectors.

Interview questions
Why not run at a very large CFL since the scheme is implicit?

The linear system is solved only approximately, and the Jacobian is a first-order approximation of the second-order residual. Too large a step makes the update inconsistent and the residual stalls or diverges, as the 12/14 corner and the first CFL settings showed.

What is a Krylov subspace, in one breath?

The space spanned by the residual and its repeated products with the matrix: \(\mathbf{r}_0, \mathbf{A}\mathbf{r}_0, \mathbf{A}^2\mathbf{r}_0\) and so on. GMRES searches it for the correction with the smallest residual, adding one dimension per iteration, and only ever touches \(\mathbf{A}\) through matrix-vector products. That is why it fits a sparse matrix that changes every step and is spread over MPI ranks.

Why FGMRES rather than GMRES, and why ILU?

In parallel SU2 the ILU preconditioner acts on each rank's block of the matrix, so the preconditioner is not one fixed matrix; FGMRES allows that by storing the preconditioned vectors and building the update from them. ILU is the standard cheap approximation of the matrix for this kind of sparse system: an LU factorisation that discards fill-in, so it costs about as much as the matrix itself to store and apply. The cost of the flexibility is one extra set of 15 vectors, negligible here.

Why 4 MPI ranks on an 8-core runtime?

It was an operational choice on the 8 vCPU runtime, recorded in the solver block of every result, not an optimized one. The Task 1 timing on the small wedge showed a speed-up of only 1.12 from serial to 2 ranks (runs/task1/README.md), so the gain from more ranks on a 30 000-cell mesh is modest, and the pool wall time of 195 to 581 s per case was acceptable.

Definition

A Gaussian process is a prior over functions: any finite set of function values is jointly Gaussian with a mean and a covariance given by a kernel k(x, x'). Conditioning on observed data gives a posterior with a closed-form mean and variance at any new point. One GP is fitted per objective: y1 = recovery_total and y2 = log q_peak. Inputs are scaled to the unit square. The kernel is Matern 5/2 with one lengthscale per input (automatic relevance determination).

A distribution over functions. Before any data, the GP says: the value of the function at any design \(\mathbf{x}\) is a Gaussian random variable with mean \(c\) and variance \(\sigma_f^2\), and the values at two designs \(\mathbf{x}\) and \(\mathbf{x}'\) are correlated by \(k(\mathbf{x}, \mathbf{x}')/\sigma_f^2\), a number between 0 and 1 that falls as the scaled distance \(r\) between them grows. A random draw from this prior is a smooth surface whose bumps are about one lengthscale \(\ell\) wide and about \(\sigma_f\) high. The kernel is the whole model: it says nothing about where the function is, only how smooth it is and how far apart two designs must be before their values become independent.

Conditioning on data. Take the \(n\) observed values \(\mathbf{y}\) and the unknown value \(f_*\) at a new design. Together they are one Gaussian vector with covariance built from the kernel: \(\mathbf{K}\) among the data (plus the noise on its diagonal), \(\mathbf{k}_*\) between the data and the new point, and \(k_{**}\) at the new point. A Gaussian vector conditioned on some of its components is again Gaussian, with a closed-form mean and variance. The posterior mean is a weighted sum of the observed values, with weights \(\boldsymbol\alpha = (\mathbf{K} + \sigma_n^2\mathbf{I})^{-1}(\mathbf{y} - c)\) that are computed once and reused at every new point. The posterior variance starts at the prior \(\sigma_f^2\) and is reduced by the amount the data explain; near a data point it falls almost to the noise level, far from all data it returns to the prior. No training loop is needed for the prediction itself: it is linear algebra.

What the hyperparameters do. The lengthscales \(\ell_1, \ell_2\) set how fast the correlation decays along \(\theta_1\) and \(\theta_2\); a different value per input is called automatic relevance determination, because an input with a very long lengthscale hardly matters. The signal variance \(\sigma_f^2\) sets the vertical scale of the prior. The noise variance \(\sigma_n^2\) is the part of each observation the smooth function is not asked to reproduce. The constant \(c\) is the level the prior returns to away from the data. The Matern 5/2 form makes the function twice differentiable: smooth, but not as rigid as the squared exponential, whose draws are infinitely differentiable and whose covariance matrices become singular on near-linear data.

Fitting. The hyperparameters are chosen to maximise the log marginal likelihood, the probability of the observed \(\mathbf{y}\) under the prior with the function integrated out. It has two parts that pull against each other: a data-fit term, which rewards a covariance that makes the observed values probable, and a complexity term \(-\tfrac{1}{2}\log|\mathbf{K}+\sigma_n^2\mathbf{I}|\), which penalises a covariance that could explain anything. This is why the GP does not need a validation set to choose its smoothness. The optimum is found by gradient ascent on the log of each parameter, from three starting lengthscales, and the best of the three is kept.

Numerics and cost. Everything goes through one Cholesky factorisation \(\mathbf{K} + \sigma_n^2\mathbf{I} = \mathbf{L}\mathbf{L}^{\mathsf T}\), which costs \(n^3/3\) operations once per fit; with \(n = 92\) that is nothing. A prediction then costs \(n\) operations for the mean and \(n^2\) for the variance per point, so a 201 by 201 grid is cheap. A tiny jitter on the diagonal keeps the factorisation stable when two designs are nearly identical. The outputs are standardised before fitting so that the three starting values and the noise floor mean the same thing for recovery and for \(\log q\).

Reading the fitted values here. The lengthscales are several box widths and the fitted signal standard deviation is about nine standard deviations of the data, with a mean of about minus five. Taken together, this is the kernel's way of describing a nearly linear surface: a very wide, very tall bump of which the box sees only a gently curved slice. The data then pin where that slice goes. Two designs at opposite corners of the box still have a prior correlation of 0.97 in recovery, so one point tells the model a lot about every other point, and the noise is what remains after the smooth surface is removed.

Interview questions
Why a GP and not a neural network?

Because on this problem it was measured. The same replay was run with a deep ensemble of five small networks (runs/replay/2026-11-02_mlp, settings fixed before the run): the GP is 2 to 10 times more accurate on held-out designs at every budget, worse for the ensemble in 10 of 10 seeds on identical training sets, and about a quarter of the cost per step. With two inputs and under fifty smooth samples the GP's prior is the right inductive bias, its intervals come from the posterior, and it needs no GPU. EHVI with the ensemble still finds the whole front by 32 runs, so the active-learning conclusion does not depend on the choice (backup slide B7).

Explain in two sentences how a GP turns 92 numbers into a surface with error bars.

The kernel says how strongly the recovery at two designs is correlated as a function of their distance, so the 92 observed values and the unknown value at any new design form one big Gaussian vector. Conditioning that Gaussian on the 92 known entries gives the mean and variance at the new design in closed form: the mean is a weighted sum of the data, the variance is the prior variance minus what the data explain.

How are the lengthscales chosen, and why is that not overfitting?

By maximising the marginal likelihood, which integrates the function out and so contains a built-in penalty, the log determinant of the covariance, against kernels that could fit anything. A lengthscale too short makes the determinant large and loses; too long makes the data improbable and loses. With 92 points and 4 hyperparameters per output there is little room to overfit, and the held-out error and the coverage in the replay are the independent check.

Why Matern 5/2 and not the squared exponential?

Matern 5/2 is twice differentiable, which matches smooth but not analytic responses, and it is less prone to ill-conditioned covariance matrices than the squared exponential on near-linear data. It is the default choice in the Bayesian optimization literature.

That the function barely bends across the box in that direction: it is close to linear.

What is the posterior variance at a training point?

Close to the noise variance: the data explain almost all of the prior variance there. Away from all data it returns to \(\sigma_f^2\). With lengthscales of several box widths, no point in the box is far from the data, so the latent variance stays small everywhere and the predictive interval is set mostly by \(\sigma_n^2\) (entry 18).

Why is q_peak modeled in the log?

q spans a factor of about 2 across the pool and relative errors matter, so the log makes the noise and the lengthscales uniform across the range.

Definition

In minimization form f1 = minus recovery and f2 = log q_peak. Point j dominates point i if f_j is no worse in both objectives and strictly better in one. The Pareto front is the set of non-dominated points. The hypervolume is the area dominated by the front and bounded by a reference point worse than every point. Hypervolume regret is one minus the hypervolume of the selected points' front over the hypervolume of the true pool front. Zero regret means the selected points contain the whole true front.

Why a front and not one best design. The two objectives conflict. A design with higher total pressure recovery tends to have higher peak heat flux, so no single design is best at both. The Pareto front is the honest answer to "what is the best trade-off": each point on it is the best recovery available for its heat flux, and the designer picks a point by deciding how much heating to accept. Every design off the front is beaten on both objectives by some design on it, so it can be discarded.

Dominance, step by step. Work in minimisation form, with f1 equal to minus recovery and f2 equal to the log of peak heat flux, so smaller is better in both. Design j dominates design i when f1 and f2 of j are both no larger, and at least one is strictly smaller. Two designs where each is better in one objective do not dominate each other, and both can stay on the front. Identical designs do not dominate each other either.

Two ways to find the front. The all-pairs method compares every design with every other. It builds one boolean matrix for "j is no worse than i in both" and one for "j is strictly better in at least one", and marks i dominated if any j satisfies both. It costs the square of the number of designs, which is trivial for 92 pool points and is what the replay and the acquisition use. The sort-and-sweep method sorts the designs by f1, then walks from the best f1 to the worst while remembering the lowest f2 seen. A design joins the front only if its f2 is below that running minimum, because every earlier design has a better or equal f1, so it can only survive by being better in f2. It costs one sort, so it handles a 40 000-point prediction grid. Both give the same answer on the same data.

Observed, predicted and uncertain fronts. The front of the simulated runs is exact for the runs that exist. To say where the true front lies between them, the study applies the same sweep to the GP posterior mean on a dense grid of angles, with the total-turning gate removing infeasible points. To show how uncertain that is, it draws joint samples of both objectives from the two GPs, takes each sample's front, and reports the spread of the best recovery at each heat-flux level. A narrow band means the models agree about the trade-off, and a wide band marks where another simulation would help.

From a front to a number. To compare two sets of designs, or to decide which design to simulate next, the front is reduced to its hypervolume, the area it dominates up to a fixed reference point worse than every design. A new design raises the hypervolume only if it lies outside the area already dominated, so the increase measures how much it extends or fills out the front. Expected hypervolume improvement is the average of this increase over the GP's uncertainty about the candidate.

Interview questions
What is a Pareto front, in one breath?

The set of designs where you cannot improve recovery without raising heat flux, or lower heat flux without losing recovery. Every other design is beaten on both objectives by one on the front, so the front is the full list of reasonable trade-offs.

How do you compute it, and why is the sweep correct?

Sort by f1 and walk left to right, keeping a design only if its f2 is below every f2 so far. Every earlier design has an equal or better f1, so a later design can only escape being dominated by having a lower f2. Hypervolume rewards both closeness and spread along the front with one number, needs no knowledge of the true front during the search, and is the quantity EHVI maximizes in expectation, so the comparison is fair to the acquisition function.

Does the reference point choice change the verdict?

It changes the numbers but not the ordering here, because the reference is fixed from the whole pool for every strategy and seed. A regret of zero is independent of the reference point.

Definition

A scalar surrogate predicts one number per design. An operator model predicts a whole function per design. Definition

The three-ramp inlet has six inputs: three ramp angles, and the flight Mach number, altitude and wall temperature. The designer chooses the angles. The flight condition is not chosen; it varies over an envelope. The low-fidelity model is Euler CFD for recovery and the Eckert flat-plate relation on the Euler wall state for heating. The robust query asks for the angles with the best nominal recovery, with the heat flux under a cap at every envelope point.

Definition

A gate is a pure function of the parameters that refuses a design before a mesh exists. Each message names the gate, the value and the limit.

  • Gate 1, attached shocks: theta1 at most theta_max(M_inf) minus 2 degrees; theta2 at most theta_max(M1) minus 2 degrees.
  • Gate 2, shock-on-lip feasibility: the lip is at least 0.02 m downstream of the corner and below 0.6 of the domain height.
  • Gate 3, duct height at least 0.008 m.
  • Gate 4, total turning theta1 plus theta2 at most 24 degrees (26 at Task 0, trimmed on the 12/14 evidence).
  • Gate 5, wall-cell Reynolds number on ramp 2 at most 50.

Interview questions
Is gate 4 physics or a patch?

It is a design-space definition made on recorded evidence: the laminar solution at 26 degrees total turning does not reach a steady state. Whether the real flow separates there is not claimed. Why a 2 degree margin on detachment?

theta_max is an inviscid value; the boundary layer displaces the ramp and the shock is slightly stronger. Two degrees keeps the shocks attached with margin without excluding useful designs: theta_max is 38.8 degrees at Mach 4 and the box ends at 12.

Definition

Three checksums protect the chain. The mesh fingerprint is a hash of the mesh the staging side built; the worker rebuilds the mesh from the parameters and must get the same fingerprint. The config hash covers the lines of case.cfg that SU2 reads, not the comment lines. Why did the whole-file hash fail across machines?

Definition

Colab cannot accept inbound connections, so jobs travel through a shared Drive folder. A job is one JSON file in jobs/ with the parameters, the code commit, the config hash and the mesh fingerprint. The worker polls the folder every 20 seconds, writes flag files in runs/<id>/status/ (0-seen, 1-running, 2-done, 2-failed), rebuilds the mesh, checks the fingerprint and hash, runs SU2 with mpirun, and writes result.json with its digest. A heartbeat file is updated while a case runs. After a restart, a 1-running job whose heartbeat is older than 10 minutes is re-run once; finished jobs are never repeated.

Interview questions
What happens if Colab disconnects in the middle of a run?

The flag stays at 1-running and the heartbeat stops. The next worker sees a stale heartbeat, re-runs the job once and writes a fresh result. Finished runs have 2-done flags and are not touched. Fault F8 tests this with a killed process.

Why does the worker rebuild the mesh instead of downloading it?

The mesh is a few megabytes and deterministic from the parameters at a given commit. Rebuilding keeps the job file at 600 bytes and gives an independent check: if the fingerprints differ, the two sides are not running the same geometry and SU2 is not started.

What happens if the worker dies but SU2 keeps running?

SU2 runs in its own session, so that a timeout can kill its whole process group, and it survives a worker that dies alone. In the real-SU2 fault run (R5) a restarted worker then started a second SU2 in the same folder; the record was still right, because both runs were the same deterministic case, but two writers in one folder is unsafe. The worker now stops any process still running in the run folder before it starts a job (R5g: one solver at a time). A Colab runtime restart ends every process, so this needs the Python process to die alone, for example from an out-of-memory kill.
