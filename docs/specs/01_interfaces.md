## Case parameters (`params.json`)

Validated by `mcp_server/schemas.py` (pydantic) and by `physics/gates.py`.

| Field | Type / bounds | Default | Notes |
|---|---|---|---|
| family | "inlet2r", "wedge", "cylinder" | required | |
| theta1_deg | float, [5, 12] (inlet2r); [2, 20] (wedge) | required for inlet2r, wedge | |
| theta2_deg | float, [5, 14] | required for inlet2r | ignored otherwise |
| radius_m | float, [0.002, 0.05] | 0.010 | cylinder only |
| mach | float, [3.0, 5.0] | 4.0 | warning if not 4.0 |
| altitude_km | 30 (only value in the table) | 30 | lookup in physics.constants |
| T_wall_K | float, [250, 1200] | 300.0 | ignored for EULER |
| solver | "NAVIER_STOKES", "EULER", "RANS_SA" | "NAVIER_STOKES" | RANS_SA: Spalart-Allmaras, no transition model, sensitivity runs only (tag `sensitivity`) |
| mesh_level | "coarse", "medium", "fine" | "medium" | |
| save_volume | bool | false | volume CSV (large) for validation only |
| tag | str, [a-z0-9_-]{1,32} | required | "val", "pool", "confirm", "test", ... |
| max_iter | int, [100, 20000] | 6000 | |

`case_id = f"{family}-{sha256(canonical_json(params))[:10]}"` where canonical_json sorts keys and
writes floats with `repr`. Same params, same id; the tag is part of params.

Physics gates (`physics/gates.py`, run by `validate_config` and `create_case`, each returns a
list of error strings, empty when OK):
1. Attached shocks: theta1 <= theta_max(M_inf) - 2 deg; theta2 <= theta_max(M1) - 2 deg.
2. Shock-on-lip feasibility: x_P - X1 >= 0.02 m and y_P <= 0.6 y_top.
3. Duct height h >= 0.008 m.
4. Total turning theta1 + theta2 <= 24 deg (design-space definition; 26 at Task 0, trimmed on
   2026-11-01 because the laminar solution at 26 deg total turning does not converge, see
   runs/dev/2026-11-01_inlet_box_diagnostics).
5. Wall-cell Reynolds number on ramp 2 at the requested first-cell height <= 50.

## Derived geometry (`geometry.json`, written next to the mesh)

Keys: X1, L_d, x_in, y_top, delta_ext_deg, theta_t_deg, C, P (lip), E_body, E_cowl, G (cowl
outer end), h_duct, beta1_deg, beta2_abs_deg, M1, M2_inviscid, p_th_over_p_inf_inviscid,
recovery_2shock_inviscid, body_length. All floats, SI, 6 significant digits.

## Mesh files

- `mesh.su2`: SU2 ASCII format, NDIME=2, quads (`9`), boundary lines (`3`), markers below.
- `mesh_markers.json`: `{marker_name: [node_ids]}` for splitting SU2's surface CSV by marker,
  plus `{"nodes": N, "cells": M, "level": ..., "first_cell_m": {marker: value}}`.
- `mesh_quality.json`: min angle (deg), max aspect ratio, max wall-normal growth, number of
  inverted cells, first-cell heights per wall, duct height, pass flag and the list of failures.

Markers:

| Family | Markers |
|---|---|
| inlet2r | body, cowl, symmetry, inlet, top, outlet_duct, outlet_ext |
| wedge | body, symmetry, inlet, top, outlet |
| cylinder | wall, symmetry, farfield, outlet |

`body` for the inlet is one marker from the leading edge to the throat; the postprocess splits it
at x = X1 using coordinates. `cowl` is inner plus outer surface; split by side of the lip using
the geometry.

## SU2 config (`case.cfg`)

Generated by `cases/config.py: render(params, geometry, mesh_markers) -> str` from a template
with explicit placeholders. No key is written that is not in the pinned SU2 version's
`config_template.cfg` (Task 1 checks this with a script). Markers used in the config must all
exist in `mesh_markers.json` (assert). The function is pure: same inputs, same text.

Output requested from SU2: `history.csv` every iteration with groups ITER, RMS_RES, MAX_RES,
AERO_COEFF, HEAT, FLOW_COEFF, CFL_NUMBER, LINSOL. SU2's CSV writers hold only the conservative
variables (PointID, x, y, Density, Momentum, Energy; they ignore `VOLUME_OUTPUT`), so there is no
heat flux in them. The surface and volume outputs are therefore Tecplot ASCII
(`OUTPUT_FILES= ( SURFACE_TECPLOT_ASCII, TECPLOT_ASCII )`): `surface_flow.dat` always, on
`MARKER_PLOTTING= (body, cowl, outlet_duct)` (inlet), and volume `flow.dat` only when
`save_volume`. Both carry x, y, Density, Momentum_x/y, Energy, Pressure, Temperature, Mach,
Pressure_Coefficient, Velocity_x/y, Laminar_Viscosity, Skin_Friction_Coefficient_x/y, Heat_Flux,
Y_Plus. SU2 also writes `restart_flow.dat`. `postprocess.tecplot` reads these files.

## Queue transport (decided 2026-11-01 after Task 0)

Claude Code runs in a cloud session with a Google Drive connector; there is no synced folder
and the container cannot see Drive. Consequences:
- The queue carries **parameters and results only**, never meshes. The worker regenerates the
  mesh and config in Colab from `params.json` using the same repository commit. Byte hashes of
  `mesh.su2` differ between machines (last digit of a coordinate, numpy build), so `create_case`
  records `mesh_fingerprint` (sha256 of coordinates rounded to 1 nm, cell connectivity and marker
  node ids; `geometry.structured.mesh_fingerprint`) and `mesh_bbox` (debugging aid) in `job.json`,
  and the worker compares fingerprints, not bytes, before running SU2 (mismatch -> failed with
  reason mesh_mismatch, detail with the bbox difference); `config_sha256` is the sha256 of the lines
  of `case.cfg` that SU2 reads (comment and blank lines left out, `worker.make_case.config_sha256`),
  because the geometry comment line carries floats whose last digit differed between the container
  and Colab (pool job inlet2r-db92dcf68d, 2026-11-01). The worker and `ingest_result` also accept the
  whole-file sha256 for job files staged before that change, which only helps when the whole file
  is byte-identical on both machines; a job refused for the comment-line difference has to be
  re-staged with the new hash (done for the 63 pool jobs on 2026-11-02).
- Digests: the worker writes `runs/<case_id>.result.sha256` next to each result and
  `runs/<case_id>.error.sha256` for each failure (sha256 of the file bytes), back-filled at start-up.
  `ingest_result` / `ingest_error` take the digest as an optional argument and refuse a text that
  does not match it; `mcp_server.ingest_files` requires the digest file unless told otherwise. Reason:
  on 2026-11-01 a base64 copy retyped by a model altered 2 of 4 result files (one mixed fields of
  two records); only a digest written at the source catches that.
- `--retry-reason R`: at start-up the worker clears `2-failed` (and `1-running`) of jobs whose
  `error.json` reason is R, renames `error.json` to `error.retried.json` and deletes the digest.
- Files cross Drive through the connector: the MCP server writes the job directory to a local
  staging folder `$SU2_QUEUE_DIR` in the container; Claude uploads `job.json` (which embeds
  params, geometry summary, mesh_fingerprint, config_sha256, code commit) to Drive folder
  `su2queue/jobs/` as a single small JSON file named `<case_id>.json`, and later downloads
  `su2queue/runs/<case_id>.result.json` written by the worker. Large files (history, surface
  CSV, log) stay in Drive under `su2queue/runs/<case_id>/` and are fetched only for cases we
  commit to `runs/` (validation, confirmation, and a sample of pool points), gzip-compressed.
- The 96-point pool crosses Drive as ONE file: the MCP tool `export_batch(case_ids)` bundles the
  staged `job.json` dicts into `jobs/<batch_id>.batch.json` (`{batch_id, created_at, code_commit,
  jobs}`, batch_id = first 10 hex of sha256 of the sorted case ids), and the worker treats every
  entry like a single job file (same validation, same state logic by `runs/<case_id>/`, oldest
  `created_at` first) and never rewrites the batch file. Pool rows excluded by a physics gate or
  the schema are not fatal: `queue_batch` lists them under `skipped` and carries on.
- The LLM is therefore a courier for JSON files; it never changes their content. Every upload
  and download is logged by the MCP `record_transfer` tool so the audit trail is complete.
- Drive folder ids (not secrets): root `su2queue` 198Hy62zhAcDo3LIn2UZhjWsEFvhH_beo; children
  `jobs` 1buszeVt7ApYdF_-tJxKmVRhjCfXK2t0U and `runs` 1rYaDOfiIx6r0myJ70Oh4vVnvTZWFfpSW
  (also in `mcp_server/drive_folders.json`).

## Job directory (local staging and Colab) layout

```
$SU2_QUEUE_DIR/jobs/<case_id>/                (local staging, created by create_case)
  params.json  geometry.json  mesh.su2  mesh_markers.json  mesh_quality.json  case.cfg
  job.json                 {case_id, params, created_at, mesh_fingerprint, mesh_bbox, config_sha256,
                            code_commit, timeout_s, max_cores}   <- the only file uploaded
/content/drive/MyDrive/su2queue/jobs/<case_id>.json      (uploaded job.json)
/content/drive/MyDrive/su2queue/runs/<case_id>/          (written by the worker in Colab)
  params.json geometry.json mesh_markers.json mesh_quality.json case.cfg
  status/  0-seen 1-running 2-done | 2-failed  (flag files, atomic write then rename)
  heartbeat.json  log.txt  history.csv  surface_flow.dat  [flow.dat]  solver_version.txt
  result.json  error.json
/content/drive/MyDrive/su2queue/runs/<case_id>.result.json   (copy of result.json, downloaded)
/content/drive/MyDrive/su2queue/worker/heartbeat.json
```
Status is derived from the flag files; nothing is ever deleted or moved by the worker; re-runs
overwrite outputs. A job is pending when `jobs/<case_id>.json` exists and `runs/<case_id>/`
has no `status/2-*` flag.

## Run record (`result.json`), also copied under `runs/<tag>/<case_id>/` in the repo

```
{
 "case_id": str, "params": {...}, "geometry": {...},
 "mesh": {"level": str, "nodes": int, "cells": int, "quality": {...}},
 "solver": {"name": "SU2_CFD", "version": str, "command": str, "n_cores": int,
            "config_sha256": str},
 "run": {"started_at": iso, "finished_at": iso, "wall_time_s": float, "iterations": int,
         "exit_code": int, "worker_id": str, "runtime": {"nproc": int, "ram_gb": float}},
 "convergence": {"rms_rho_log10_start": float, "rms_rho_log10_end": float,
                 "drop_orders": float, "drift_pct": {"recovery_total": float, "q_peak": float},
                 "status": "converged|stationary|not_converged|diverged|timeout|error"},
 "metrics": {"recovery_throat": float, "recovery_total": float, "recovery_total_bulk": float,
             "mach_throat_massavg": float, "capture_ratio": float, "q_peak_W_m2": float,
             "x_q_peak_m": float, "q_peak_cowl_W_m2": float, "heat_load_body_W_per_m": float,
             "su2_avg_totalpress_Pa": float, "p0_inf_Pa": float},
 "code": {"git_commit": str, "dirty": bool},
 "files": {"history": "history.csv", "surface": "surface_flow.dat", "log": "log.txt"}
}
```
Committed per run: `params.json`, `geometry.json`, `case.cfg`, `result.json`, `history.csv`,
`mesh_quality.json`, `solver_version.txt`, `surface_flow.dat.gz`, `log.txt.gz`. The volume `flow.dat`
stays on Drive; `result.json` records their sha256. A number appears in docs or slides only if its
`case_id` is in `runs/`.
