# Fault injection: what stops a bad input or a failed run

The agent layer is tools plus gates plus logs. This folder shows, with tests that run without SU2,
which layer catches each fault and what the user sees. The LLM chooses no sampling point and edits no
job file; it moves JSON between the MCP server, Drive and the worker.

Re-run the matrix (no SU2 needed, about 10 s):

    python -m pytest -q tests/test_faults.py

This rewrites [fault_matrix.md](fault_matrix.md); commit the result. Run the whole file: if a fault
test is missing from the run (for example with `-k`), the last test skips and leaves the committed
matrix alone. The rows are generated by the tests, not typed.

## The layers, in the order a job meets them

1. **Schema** (`mcp_server/schemas.py`): types and bounds of every parameter. Stage `schema`.
2. **Physics gates** (`physics/gates.py`, five gates of `docs/specs/01_interfaces.md`): attached shocks,
   shock on lip, duct height, total turning at most 24 deg, wall-cell Reynolds number. Stage `gates`.
3. **Mesh quality** (`worker/make_case.py`): inverted cells, minimum angle, first-cell height, growth,
   aspect ratio. Stage `mesh_quality`.
4. **Config keys** (`cases/check_keys.py`): every key of `case.cfg` must exist in the pinned SU2
   v8.2.0 template. Stage `config_keys`.
   Layers 1 to 4 run in `validate_config` and again in `create_case`; a failure writes nothing.
5. **Worker checks** (`worker/run_worker.py`), before SU2 starts: the worker regenerates mesh and
   config from `params`, and compares `mesh_fingerprint` and `config_sha256` with the job file. A
   mismatch is `mesh_mismatch` or `config_mismatch`; SU2 is not started.
6. **Worker failure records**, after SU2 starts: `timeout` (process group killed), `nonzero_exit`
   (log tail kept), `nan` (diverged residual, history kept), `postprocess_error`. Each writes
   `error.json` with a reason and flags `2-failed`. A worker killed mid-run is found by its stale
   heartbeat and the job is re-run once (F8).
7. **Ingest checks** (`mcp_server/queue.py`, `ingest_result`): the result must carry the staged
   `case_id`, `mesh_fingerprint`, `config_sha256` and params, and must match the sha256 digest the
   worker wrote next to it on Drive when that digest is given. A bad result is refused and nothing
   is stored. A diverged or timed-out run must be reported with `ingest_error`.
8. **Postprocess checks** (`postprocess/surface.py`): "solution diverged" when the surface file has
   a non-finite value, pressure above 1e7 Pa or density above 100 kg/m^3; "check the units" only
   when a finite, sane state disagrees with SU2's own pressure or Mach column.

## Faults tested

F1 schema, F2 physics gate, F3 inverted cell, F4 unknown SU2 key, F5 solver divergence, F6 solver
crash, F7 timeout, F8 killed worker, F9 tampered job, F10a and F10b tampered result. F8 is run by
`tests/test_worker_resume.py` (it starts a subprocess and kills it); `tests/test_faults.py` only
checks that this test exists and quotes the worker's message.

The faults are injected through the fake solver `tests/fake_su2.py` and by monkeypatching, so the
matrix shows that the gates and records work. The same chain was then run with the real SU2 binary
(next section).

## Faults through real SU2 (2026-11-03)

Spec: `docs/specs/task6b_real_su2_faults.md`. Harness: `python -m analysis.real_faults` (the real
worker on a local queue folder, the SU2 v8.2.0 release binary, one process). Matrix, generated from
the run folders: [real_fault_matrix.md](real_fault_matrix.md). Records: `runs/faults/2026-11-03/`.
Control case R0: wedge, coarse mesh, laminar; 672 iterations in 21 s; body heat load 4718.25 W/m.

What held, as designed:

- R2, SU2 killed by SIGKILL mid-run: 2-failed, reason nonzero_exit, exit code -9, 55 history rows kept.
- R3, timeout 10 s: 2-failed, reason timeout; no SU2 process left afterwards.
- R4, worker and SU2 both killed (a runtime restart): the job was re-run once, and its metrics equal
  R0's exactly.
- R6, unknown key reaching SU2 (gate F4 bypassed): SU2 itself stops in 0.01 s with exit code 1 and
  names the line. Gate F4 refuses the same key before staging, so a bad key never takes a Colab slot.
- R8, edited mesh fingerprint: mesh_mismatch, SU2 never started.

What did not behave as the spec expected, and what was done:

1. **R9, a job file not made by create_case reached SU2.** The physics gates ran only in the MCP
   layer (`mcp_server/queue.py`); the worker regenerates mesh and config and compares hashes, but
   `worker.make_case.make` accepts 12/14. A job file for 12/14 written with `make` was run: SU2
   diverged after 4347 iterations (450 s), with the last history line equal to the 2026-11-01 record
   `runs/dev/2026-11-01_inlet_grid_study_ef03/12_14_medium` to every digit, and the worker flagged
   2-failed, reason nonzero_exit ("SU2 has diverged (Residual > 10^20 detected)"). The record was
   correct, but a solver slot was spent on a case a gate refuses. **Guard:** the worker checks the
   physics gates again before it builds anything (`worker/run_worker.check_regenerated`, reason
   `gates`; test `tests/test_worker_guards.py`). **R9g**, the same job after the guard: refused at
   `gates` in 0 s, SU2 not started.
2. **R5, two solvers in one folder.** When the worker process dies alone, SU2 keeps running (it is in
   its own session so that a timeout can kill its whole process group). A restarted worker that
   treats the job as a crash victim started a second SU2 in the same folder; at most 2 ran at once.
   The final record was correct here (metrics equal R0), because both runs were the same
   deterministic case, but two writers in one folder can leave mixed files. **Guard:** before it
   runs a job, the worker stops any process whose working directory is the run folder
   (`stop_leftover_solvers`, logged; test `tests/test_worker_guards.py`). **R5g** after the guard:
   "stopped 1 leftover solver process(es)", at most 1 solver at once, metrics equal R0.
   On Colab a runtime restart ends every process, so this case needs the worker to die without the
   runtime (for example an out-of-memory kill of the Python process).
   R5g ran with the guard in the working tree before its commit; the records say commit a731580.

Findings that need no guard, reported as observed:

- **R1, a bad template edit (CFL 1e4 fixed) did not diverge.** The implicit solver converged in 201
  iterations, and the heat load differs from R0 by 7e-6 relative. The spec expected a divergence; on
  this case there was none. R9 supplied the real divergence through the worker instead.
- **R7, a reversed element is repaired by SU2.** SU2 printed "There has been a re-orientation of 1
  QUADRILATERAL volume elements" and the result equals R0 to every digit. Reversed node order is not
  a test of the mesh gate.
- **R7b, a tangled cell is not detected by SU2.** One node moved past the opposite corner of its
  cell: SU2 re-oriented one element, ran, converged (1078 iterations) and reported a body heat load of
  4887.01 W/m, 3.6 percent above R0, with exit code 0 and no warning. Only the mesh-quality gate
  (inverted cells, minimum angle) stops this, and the worker never runs a mesh it did not build and
  check itself.
- Every clean run prints "There has been a re-orientation of 200 LINE surface elements": SU2 flips
  the boundary edges our mesh writer emits. It is harmless (SU2 fixes it on read) and is recorded
  here so that nobody mistakes it for a fault.

The input faults F1 and F2 were also sent through the live MCP tool `validate_config` from Claude
Code (`docs/transcripts/2026-11-03_mcp_input_faults.md`). The first three calls left out the
required `tag` field, a real mistake by the agent, and the schema refused them and named the field.

## One real failure, end to end

The inlet at theta1 = 12 deg and theta2 = 14 deg (26 deg total turning) was run with SU2 v8.2.0 on
the medium and fine meshes, at two entropy fixes. The residual fell to about -7.5 by iteration 1200,
then grew and the run exited with an error (4347 iterations on the medium mesh). Records:
`runs/dev/2026-11-01_inlet_grid_study_ef03/` (cases `12_14_medium`, `12_14_fine`) and the diagnostics
in `runs/dev/2026-11-01_inlet_box_diagnostics/`.

- Diagnosis (recorded, not proven): theta2 = 14 deg alone converges (5/14 and 8/14 do), so the
  failure is the 26 deg total-turning corner. The residual pattern (falls to -7.5, then grows at
  any CFL) is that of a separation that does not settle to a steady state; the flow field was not
  inspected to confirm it.
- Guard: gate 4 (total turning at most 24 deg, trimmed from 26 on 2026-11-01), which F2 exercises:
  `theta1 = 12, theta2 = 14` is now refused at stage `gates` before any mesh is built.
- Postprocess: the saved surface file of the diverged run has pressures up to about 8e10 Pa and
  densities up to about 1e8 kg/m^3. The validation report (`python -m postprocess.report`) used to
  say "check the units" for it; it now says "solution diverged".

## Two more real failures, from the pool campaign (2026-11-01 and 2026-11-02)

Both are failures of the tooling, not of the physics, and both were caught by a guard that then
turned out to be wrong in the other direction. Records: `PLAN.md` Day-1 status log and
`docs/transcripts/2026-11-02_worker_restart_and_retry.md`.

1. **An over-strict guard: `config_mismatch` on a comment line.** The worker refused pool job
   `inlet2r-db92dcf68d` because the whole-file sha256 of `case.cfg` differed between the container
   and Colab. The lines SU2 reads were identical; one geometry number in a `%` comment line
   (`h_duct`) differed in its last digit, by 3e-18. By 20:30 UTC on 2026-11-01 about 62 of the 92
   pool jobs had been refused for the same reason. Fix: `worker/make_case.config_sha256` hashes only
   the lines SU2 reads (test `tests/test_make_case.py::test_config_sha256_ignores_comment_lines_only`).
   A second error followed from the first: the restarted worker re-ran the 63 refused jobs and all
   failed again within four minutes, because their job files still carried the old whole-file hash
   that can never match on Colab. The 63 jobs were re-staged with the new hash as single job files;
   all 92 pool points then converged (`docs/validation/2026-11-01_colab_records.md`). The failure
   record of `inlet2r-db92dcf68d` is at commit 915f5f8; its retry's result replaced it.
2. **A transfer without a check: corrupted result files.** Results cross from Drive to the repo as
   text through the connector, and an agent retyping base64 altered 2 of 4 result files on
   2026-11-01 (one mixed the fields of two records). Guard: the worker now writes a sha256 digest
   next to every result and failure (`<id>.result.sha256`, back-filled at start-up for older
   records, test `tests/test_worker_failures.py::test_backfill_writes_digests_for_old_results`) and
   ingest refuses a text that does not match it
   (`tests/test_ingest.py::test_ingest_checks_the_workers_digest`). The 16 pool and 13 validation
   records ingested before the digests existed were re-checked with `python -m mcp_server.verify_digests`
   (16 of 16 pool records match byte for byte). With the gate on, 6 of the 84 later transcriptions (21, 19, 19, 22 and 3 result files)
   were wrong at the first attempt and every one was caught and redone; 0 bad records entered the repo.
